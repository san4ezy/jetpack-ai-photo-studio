# Spec Delta

## MODIFIED Requirements

### Requirement: Virtual Project Folder Panel and Three-State Selection Toggle
Ліва панель MUST підтримувати завантаження зображень через Drag&Drop або клік по порожньому місцю, перемикач режимів огляду «Список / Плитки» (3 плитки по ширині зі збільшеними превью), кольорові іконки розширень файлів, іконку-галочку статусу обробки без тексту, індикатор кількості усіх версій у правому нижньому кутку превью з popup-вікном керування всіма версіями, спливаюче напівпрозоре вікно деталей файлу по правому кліку та компактну кнопку-перемикач станів виділення.

#### Scenario: Drag and drop or click empty space uploads images
- **WHEN** користувач перетягує зображення на ліву панель або клікає по її порожній області та обирає файли
- **THEN** фронтенд надсилає валідні зображення через `studio.upload_files` і оновлює список/плитки мініатюр

#### Scenario: Selection toggle cycles Select -> Select All -> Reset
- **WHEN** користувач послідовно натискає кнопку режиму виділення у шапці лівої панелі
- **THEN** цикл перемикає стан виділення `Select` → `Select All` → `Reset` (із відповідною зміною іконки та tooltip), дозволяючи мульти-виділення та вибір усіх файлів

#### Scenario: List and Tiles view toggle switches Project Folder layout
- **WHEN** користувач натискає перемикач режиму огляду в шапці Project Folder
- **THEN** відображення файлів перемикається між компактним списком і сіткою з 3 плиток по ширині зі збільшеними превью, кольоровими іконками розширень та іконкою-галокою статусу обробки без тексту

#### Scenario: Version count badge opens version management popup above Project Folder
- **WHEN** користувач клікає на число версій у правому нижньому кутку превью файлу (`1` для лише оригіналу, `1 + N` за наявності `N` збережених проміжних версій у `output/<stem>/`)
- **THEN** над панеллю Project Folder відкривається popup зі збільшеними превью оригіналу та **усіх** збережених проміжних версій (`v001`, `v002`, …), індикатором поточної активної версії «В роботі» та кнопками-іконками «Взяти в роботу», «Скачати» і «Видалити» (вимкнена лише для оригіналу) для кожної версії

#### Scenario: Version actions switch working base, download, or delete any intermediate version
- **WHEN** користувач у popup-вікні версій натискає «Взяти в роботу», «Скачати» або «Видалити» на будь-якій версії
- **THEN** «Взяти в роботу» встановлює цю версію (включно з `Оригінал` або довільною `vNNN`) як активну основу для перегляду та наступної операції без видалення інших версій; «Скачати» завантажує файл саме цієї версії; «Видалити» видаляє відповідну проміжну версію з диска та оновлює список версій і лічильник на бейджі

#### Scenario: Right-click on file item shows translucent metadata popover
- **WHEN** користувач натискає праву кнопку миші на будь-якому файлі у Project Folder
- **THEN** стандартне контекстне меню не відкривається, а натомість показується напівпрозоре спливаюче вікно з відомими подробицями файлу (ім'я, розміри в пікселях, обсяг, розширення/MIME, DPI, колірний режим, джерело, дата зміни та статус обробки)

### Requirement: Top Horizontal Toolbar and Processing Actions
Верхня панель інструментів правої робочої області MUST бути організована вертикально з рядком табів інструментів (`Upscale`, `Enhance`, `Remove BG`, `Blur BG`, `Crop`, `Resize`) зверху та блоком динамічних налаштувань обраного інструменту під табами без жорсткої надлишкової висоти; універсальний глобальний вибір формату `File Type` MUST розміщуватись у Додатковій панелі керування над панеллю інструментів як button group без текстового підпису з кнопками розширень (`AUTO`, `.PNG`, `.JPG`, `.WEBP`), кольори яких збігаються з лейблами типів файлів у Project Folder; а кнопки запуску `Process` і `Process All` у виразному зеленому кольорі та іконкова кнопка `Undo` (без тексту) MUST розміщуватися поряд у тонкій Панелі керування над Project Folder разом із кнопками групових дій та відкриття робочої папки на ПК.

#### Scenario: Secondary Control Panel hosts color-matched File Type button group without label
- **WHEN** користувач переглядає або перемикає будь-який інструмент обробки
- **THEN** у Додатковій панелі керування над панеллю інструментів відображається універсальна група кнопок вибору формату (`AUTO`, `.PNG`, `.JPG`, `.WEBP`) без підпису `File Type`, де кольори кнопок `.PNG`, `.JPG`, `.WEBP` збігаються з кольорами відповідних лейблів у Project Folder і зберігаються незалежно від обраного інструменту

#### Scenario: Selecting each tool updates dynamic option controls
- **WHEN** користувач перемикає таб інструменту в панелі інструментів
- **THEN** під рядком табів відображаються параметри лише активного інструменту (`2x / 4x` для `Upscale`; статус для `Enhance`; `Transparent / Color` + color picker для `Remove BG`; повзунок `Level` для `Blur BG`; у `Crop` — взаємно виключна група кнопок із `Keep aspect` першим, далі пресети `1:1`, `4:5`, `9:16`, `16:9`, `4:3`, `3:2` і `Custom` останнім; у `Resize` — взаємно виключна група кнопок `Keep aspect` та `Custom`), причому в обох інструментах (`Crop` і `Resize`) компактні поля `<input>` ширини та висоти завжди відображаються в одному рядку з групою кнопок (у `Crop` для всіх режимів крім `Custom` зміна однієї сторони автоматично підганяє іншу під співвідношення в межах активного зображення, а в `Crop: Custom` обидві сторони редагуються незалежно в межах зображення; у `Resize: Keep aspect` зміна однієї сторони пропорційно перераховує іншу, а в `Resize: Custom` обидві сторони редагуються незалежно із дозволеним розтягуванням)

#### Scenario: Process and Process All respect active and selected state
- **WHEN** у режимі `Select` не виділено жодного файлу
- **THEN** зелені кнопки `Process` і `Process All` розміщуються на початку Панелі керування над Project Folder, кнопка `Process All` є неактивною (`disabled`), а кнопка `Process` обробляє поточний активний файл

#### Scenario: Icon-only Undo button sits beside processing buttons and reverts last action
- **WHEN** користувач виконав одну або кілька операцій обробки (`Process` або `Process All`)
- **THEN** іконкова кнопка `Undo` (без текстового підпису, з відповідною іконкою та tooltip) поруч із `Process` / `Process All` стає активною, а при натисканні скасовує останню дію обробки (включно з фізичним видаленням створеного файла чи файлів пакетної операції та поверненням попередніх активних версій)

#### Scenario: Undo button stays disabled when undo stack is empty or worker is busy
- **WHEN** стек скасування порожній, воркер відключений або триває операція обробки/завантаження
- **THEN** кнопка `Undo` перебуває у неактивному стані (`disabled`)

#### Scenario: Open Folder button in Control Panel opens workspace directory on PC
- **WHEN** користувач натискає кнопку відкриття папки у Панелі керування
- **THEN** фронтенд викликає опкод `studio.open_folder`; якщо системне відкриття виконалось (`opened = true`), папка відкривається у файловому менеджері, а якщо системний sandbox обмежує запуск файлового менеджера (`opened = false`), фронтенд автоматично копіює точний шлях `working_dir` у буфер обміну та показує підказку (`Cmd+Shift+G` у Finder)

### Requirement: Interactive Preview Canvas with Before/After Slider and Time Machine Cascade
Полотно перегляду MUST автоматично масштабувати активну версію зображення (вписувати у доступну область, якщо воно більше за viewport, і показувати у масштабі `1:1`, якщо воно менше за доступну область), підтримувати інтерактивний слайдер «До / Після» без нативного синього виділення при перетягуванні (порівнюючи оригінал із поточною активною обробленою версією, або показуючи одиночний оригінал, коли активною основою обрано `Оригінал`), у режимі `Crop` показувати поверх зображення інтерактивну білу рамку кадрування з напівпрозорим білим затіненням зовні (приховану в інших інструментах, включно з `Resize`), підтримувати центрований перспективний каскад у стилі Apple Time Machine при мульти-виділенні (5–7 передніх карток зі збільшеним вертикальним кроком і відходом назад у темряву), кнопки масштабування (`Zoom Out`, `Fit`, `100%`, `Zoom In`) у правому нижньому кутку полотна та умовне вікно навігації («пошукач» / minimap), розташоване **над** кнопками масштабування. Під час будь-якого масштабування чи прокрутки положення й розмір рамки пошукача MUST точно відповідати тій частині зображення, яку фактично бачить користувач у viewport (зі збереженням фокусної точки при зумі), а сам пошукач MUST завжди використовувати поточну активну версію зображення (активну оброблену версію або оригінал, якщо обрано `Оригінал`).

#### Scenario: Crop tool displays movable white crop frame with white outer veil over image
- **WHEN** обрано інструмент `Crop` і на полотні відкрито одиночне зображення
- **THEN** поверх зображення відображається біла рамка розміру та співвідношення сторін обраного режиму (центрирована за замовчуванням у межах поточної активної версії, наприклад `540×540` для `1:1` на `1080×540`), а область поза межами рамки затінюється напівпрозорим білим шаром; користувач може переміщати рамку в межах зображення та змінювати її розмір полями ширини/висоти для точного піксельного кадрування без масштабування (у режимі `Resize` рамка прихована)

#### Scenario: Initial canvas scaling respects image dimensions vs viewport
- **WHEN** на полотні відкривається одиночне зображення або порівняння «До / Після»
- **THEN** зображення займає максимум доступного простору полотна, якщо його натуральні розміри перевищують доступну область, або відображається в оригінальному масштабі 100% (`1:1`), якщо воно менше за доступну область

#### Scenario: Bottom-right zoom controls scale active image and reveal minimap navigator
- **WHEN** користувач натискає кнопки масштабування (`Zoom Out`, `Fit` — розгортання на всю робочу область, `100%` — оригінальний розмір `1:1`, `Zoom In`) або використовує `Ctrl/Cmd + Wheel` над полотном
- **THEN** активне зображення (або контейнер слайдера «До / Після») плавно масштабується зі збереженням поточної фокусної точки (центру видимої області або позиції курсора при колесі миші), і щойно масштабоване зображення перевищує видимі межі полотна, **над** кнопками масштабу з'являється пошукач, який показує мініатюру зображення з рамкою видимої області та дозволяє перетягуванням/кліком точно переміщати область перегляду

#### Scenario: Minimap viewport frame always matches visible image region across zoom and pan
- **WHEN** зображення збільшене (понад межі viewport по горизонталі та/або вертикалі) і користувач масштабує його (`Zoom In`, `Zoom Out`, `100%`, `Ctrl/Cmd + Wheel`), панорамує, змінює розмір вікна або взаємодіє з пошукачем
- **THEN** центр і межі рамки пошукача завжди точно співпадають із фактично видимою користувачем часткою зображення (зокрема, коли користувач бачить центр зображення, рамка пошукача розташована по центру мініатюри, а не зміщена у бік; на краях рамка не виходить за межі мініатюри навіть при мінімальному розмірі рамки, нестандартних співвідношеннях сторін чи наявності скролбарів)

#### Scenario: Minimap navigator always uses latest processed image when available
- **WHEN** активний файл має оброблену версію, обрану в роботу (включно з перемиканням між `v001`, `v002` чи повторною обробкою), або користувач перемкнув основу на `Оригінал`
- **THEN** пошукач відображає мініатюру саме поточної активної версії та обчислює пропорції й рамку видимої області відносно її актуальних розмірів; після вибору `Оригінал` або очищення результатів пошукач автоматично перемикається на оригінал

#### Scenario: Single processed image renders interactive Before/After slider
- **WHEN** обрано один файл, для якого активною є оброблена версія (`is_processed = true`)
- **THEN** полотно завантажує оригінал та активну оброблену версію через `studio.get_image` і рендерить рухомий вертикальний розділювач «До / Після» з підтримкою миші/тач-подій, сумісний із поточним масштабом, без артефактів нативного виділення

#### Scenario: Single file with Original selected as active base renders single original view
- **WHEN** користувач бере в роботу версію `Оригінал` для файлу, що вже має збережені версії в `output/`
- **THEN** полотно відображає одиночний перегляд оригіналу (без слайдера «До / Після»), а інструменти `Crop` / `Resize` оновлюють розміри під оригінал, зберігаючи всі існуючі проміжні версії в списку версій

#### Scenario: Multi-selection renders Apple Time Machine cascade
- **WHEN** у режимі виділення обрано 2 або більше файлів
- **THEN** відображаються до 5–7 передніх карток без зміщення вправо (`translateX = 0`), зі збільшеним вертикальним відступом, зменшенням масштабу та затемненням/зникненням у темряву при відході назад (`translateZ`), із використанням легких прев'ю (`thumbUrl`) для задніх карток та повного перегляду активної версії для передньої картки

### Requirement: Individual and Batch Result Controls
Користувач MUST мати змогу завантажити поточну активну оброблену версію або повністю очистити всі оброблені версії файлу (іконкові кнопки `Download` і `Restore` на полотні), а також експортувати всі проміжні результати чи очистити всю папку `output/` (іконкові кнопки `Restore All` і `Download All`, розміщені у Панелі керування після блоку запуску обробки та `Undo`), об'єднані у відповідні button groups з підказками при наведенні.

#### Scenario: Per-image Download and Restore appear on processed image
- **WHEN** активна робоча версія на полотні є обробленою версією (`is_processed = true`)
- **THEN** поверх зображення відображається згрупована панель іконкових кнопок `Download` (скачує саме поточну активну версію) та `Restore` (видаляє всі збережені версії цього файлу з `output/` і повертає до оригіналу) з підказками (`title`)

#### Scenario: Bottom-right Download All and Restore All reflect processed count and busy state
- **WHEN** у `output/` немає жодної збереженої проміжної версії або триває обробка
- **THEN** кнопки `Restore All` і `Download All`, розташовані у Панелі керування після `Process`/`Process All` та `Undo`, є неактивними (`disabled`), а за наявності збережених версій і простою `Download All` скачує `.zip` архів з усіма проміжними версіями у структурі `<stem>/<stem>-vNNN.<ext>` через `studio.download_zip`, тоді як `Restore All` видаляє всі версії та підпапки в `output/`

### Requirement: Icon-First Button Ergonomics, Button Groups, and Native Context Menu Suppression
Усі кнопки дій інтерфейсу MUST використовувати зрозумілі SVG-іконки з інформативними tooltip-підказками (зокрема іконкова кнопка `Undo` без тексту), суміжні кнопки в межах однієї панелі MUST об'єднуватися у візуальні групи (`button groups`), а стандартне контекстне меню браузера/веб-в'ю MUST бути заблоковане на всьому інтерфейсі.

#### Scenario: Action buttons render icons with accessible tooltips and connected group styling
- **WHEN** інтерфейс рендерить панелі дій (Панель керування з `Process`/`Process All`, `Undo`, `Restore All`/`Download All` і `Open Folder`, шапку Project Folder, групу дій на зображенні, дії версій і панель масштабу з `Fit`/`100%`)
- **THEN** кожна кнопка дії відображається у вигляді компактної іконки з `title`/`aria-label` (без текстового лейбла на `Undo`), кнопки `Process` і `Process All` мають виразне зелене оформлення, а сусідні кнопки однієї групи візуально з'єднані в суцільну групу кнопок

#### Scenario: Default browser context menu is suppressed globally
- **WHEN** користувач виконує правий клік у будь-якій точці веб-в'ю
- **THEN** стандартне контекстне меню браузера не з'являється, а на елементах файлів відкривається лише кастомне напівпрозоре вікно деталей файлу
