# studio-web-ui Spec Delta

## MODIFIED Requirements

### Requirement: Two-Column Dark Frosted Glass Layout
Інтерфейс MUST відповідати темній напівпрозорій стилістиці JetPack (`backdrop-filter: blur`, темний фон, тонкі напівпрозорі рамки) і поділятися на ліву колонку (1/3 ширини) із тонкою однорядною Панеллю керування (без зайвих текстових заголовків на кшталт «Керування MPS») над панеллю Project Folder та праву робочу область (2/3 ширини) із такою ж за висотою тонкою **Додатковою панеллю керування** над панеллю інструментів, під верхньою `JetPackControlBar`, без дублюючого верхнього банера під час штатного підключення або після підключення.

#### Scenario: Desktop layout maintains 1/3 to 2/3 split
- **WHEN** застосунок відкривається на десктопному екрані
- **THEN** ліва колонка займає ~1/3 ширини (мін. ~300px) із тонкою однорядною Панеллю керування зверху (без текстового лейбла «Керування MPS») та панеллю Project Folder під нею, а права колонка займає 2/3 ширини з тонкою Додатковою панеллю керування тієї ж висоти над компактною панеллю інструментів, полотном перегляду та нижнім рядком статусу

#### Scenario: Redundant connection banner stays hidden during normal startup and connected state
- **WHEN** застосунок підключається у штатному режимі або вже підключений до `jetpack-daemon` через `@jetpack/client`
- **THEN** верхній `#connection-banner` залишається прихованим (`hidden`), а статус підключення та керування воркером відображаються виключно вбудованою SDK-панеллю `JetPackControlBar` (банер показується лише за потреби ручної авторизації `jetpack://pair` або при помилці підключення)

### Requirement: Virtual Project Folder Panel and Three-State Selection Toggle
Ліва панель MUST підтримувати завантаження зображень через Drag&Drop або клік по порожньому місцю, перемикач режимів огляду «Список / Плитки» (3 плитки по ширині зі збільшеними превью), кольорові іконки розширень файлів, іконку-галочку статусу обробки без тексту, індикатор кількості версій у правому нижньому кутку превью з popup-вікном керування версіями, спливаюче напівпрозоре вікно деталей файлу по правому кліку та компактну кнопку-перемикач станів виділення.

#### Scenario: Drag and drop or click empty space uploads images
- **WHEN** користувач перетягує зображення на ліву панель або клікає по її порожній області та обирає файли
- **THEN** фронтенд надсилає валідні зображення через `studio.upload_files` і оновлює список/плитки мініатюр

#### Scenario: Selection toggle cycles Select -> Select All -> Reset
- **WHEN** користувач послідовно натискає кнопку режиму виділення у шапці лівої панелі
- **THEN** цикл перемикає стан виділення `Select` → `Select All` → `Reset` (із відповідною зміною іконки та tooltip), дозволяючи мульти-виділення та вибір усіх файлів

#### Scenario: List and Tiles view toggle switches Project Folder layout
- **WHEN** користувач натискає перемикач режиму огляду в шапці Project Folder
- **THEN** відображення файлів перемикається між компактним списком і сіткою з 3 плиток по ширині зі збільшеними превью, кольоровими іконками розширень та іконкою-галочкою статусу обробки без тексту

#### Scenario: Version count badge opens version management popup above Project Folder
- **WHEN** користувач клікає на число версій у правому нижньому кутку превью файлу (`1` для лише оригіналу, `2` за наявності результату в `output/`)
- **THEN** над панеллю Project Folder відкривається popup зі збільшеними превью усіх наявних версій файлу та кнопками-іконками «Видалити», «Скачати» і «Взяти в роботу» для кожної версії

#### Scenario: Right-click on file item shows translucent metadata popover
- **WHEN** користувач натискає праву кнопку миші на будь-якому файлі у Project Folder
- **THEN** стандартне контекстне меню не відкривається, а натомість показується напівпрозоре спливаюче вікно з відомими подробицями файлу (ім'я, розміри в пікселях, обсяг, розширення/MIME, DPI, колірний режим, джерело, дата зміни та статус обробки)

### Requirement: Top Horizontal Toolbar and Processing Actions
Верхня панель інструментів правої робочої області MUST бути організована вертикально з рядком табів інструментів (`Upscale`, `Enhance`, `Remove BG`, `Blur BG`, `Resize`) зверху та блоком динамічних налаштувань обраного інструменту під табами без жорсткої надлишкової висоти; універсальний глобальний вибір формату `File Type` MUST розміщуватись у Додатковій панелі керування над панеллю інструментів як button group без текстового підпису з кнопками розширень (`AUTO`, `.PNG`, `.JPG`, `.WEBP`), кольори яких збігаються з лейблами типів файлів у Project Folder; а кнопки запуску `Process` і `Process All` MUST бути виконані у виразному зеленому кольорі та розміщені у тонкій Панелі керування над Project Folder разом із кнопкою відкриття робочої папки на ПК.

#### Scenario: Secondary Control Panel hosts color-matched File Type button group without label
- **WHEN** користувач переглядає або перемикає будь-який інструмент обробки
- **THEN** у Додатковій панелі керування над панеллю інструментів відображається універсальна група кнопок вибору формату (`AUTO`, `.PNG`, `.JPG`, `.WEBP`) без підпису `File Type`, де кольори кнопок `.PNG`, `.JPG`, `.WEBP` збігаються з кольорами відповідних лейблів у Project Folder і зберігаються незалежно від обраного інструменту

#### Scenario: Selecting each tool updates dynamic option controls
- **WHEN** користувач перемикає таб інструменту в панелі інструментів
- **THEN** під рядком табів відображаються параметри лише активного інструменту (`2x / 4x` для `Upscale`; статус для `Enhance`; `Transparent / Color` + color picker для `Remove BG`; повзунок `Level` для `Blur BG`; у `Resize` — взаємно виключна група кнопок із `Keep aspect` першим, далі популярні співвідношення сторін з іконками `1:1`, `4:5`, `9:16`, `16:9`, `4:3`, `3:2` і `Custom` останнім), причому поля вводу ширини та висоти відображаються як `<input>` лише для `Keep aspect` і `Custom` (для інших режимів — текстове відображення), числові значення автоматично підставляються відповідно до обраного режиму, а жоден режим не викривляє пропорції зображення (`Keep aspect` масштабує пропорційно, усі інші режими виконують пропорційне кадрування)

#### Scenario: Process and Process All respect active and selected state
- **WHEN** у режимі `Select` не виділено жодного файлу
- **THEN** зелені кнопки `Process` і `Process All` розміщуються на початку Панелі керування над Project Folder, кнопка `Process All` є неактивною (`disabled`), а кнопка `Process` обробляє поточний активний файл

#### Scenario: Open Folder button in Control Panel opens workspace directory on PC
- **WHEN** користувач натискає кнопку відкриття папки у Панелі керування
- **THEN** фронтенд викликає опкод `studio.open_folder`; якщо системне відкриття виконалось (`opened = true`), папка відкривається у файловому менеджері, а якщо системний sandbox обмежує запуск файлового менеджера (`opened = false`), фронтенд автоматично копіює точний шлях `working_dir` у буфер обміну та показує підказку (`Cmd+Shift+G` у Finder)

### Requirement: Interactive Preview Canvas with Before/After Slider and Time Machine Cascade
Полотно перегляду MUST автоматично масштабувати активне зображення (вписувати у доступну область, якщо воно більше за viewport, і показувати у масштабі `1:1`, якщо воно менше за доступну область), підтримувати інтерактивний слайдер «До / Після» для обробленого зображення, у режимі `Resize` показувати поверх зображення інтерактивну білу рамку кадрування з напівпрозорим білим затіненням зовні, підтримувати центрований перспективний каскад у стилі Apple Time Machine при мульти-виділенні (5–7 передніх карток зі збільшеним вертикальним кроком і відходом назад у темряву), кнопки масштабування (`Zoom Out`, `Fit`, `100%`, `Zoom In`) у правому нижньому кутку полотна та умовне вікно навігації (minimap), розташоване **над** кнопками масштабування.

#### Scenario: Resize tool displays movable white crop frame with white outer veil over image
- **WHEN** обрано інструмент `Resize` і на полотні відкрито одиночне зображення
- **THEN** поверх зображення відображається біла рамка зі співвідношенням сторін обраного режиму (центрирована за замовчуванням), а область поза межами рамки затінюється напівпрозорим білим шаром; користувач може переміщати рамку в межах зображення зі збереженням співвідношення сторін для обробки одиночного файлу, тоді як пакетна обробка використовує центровану рамку за замовчуванням

#### Scenario: Initial canvas scaling respects image dimensions vs viewport
- **WHEN** на полотні відкривається одиночне зображення або порівняння «До / Після»
- **THEN** зображення займає максимум доступного простору полотна, якщо його натуральні розміри перевищують доступну область, або відображається в оригінальному масштабі 100% (`1:1`), якщо воно менше за доступну область

#### Scenario: Bottom-right zoom controls scale active image and reveal minimap navigator
- **WHEN** користувач натискає кнопки масштабування (`Zoom Out`, `Fit` — розгортання на всю робочу область, `100%` — оригінальний розмір `1:1`, `Zoom In`) у правому нижньому кутку полотна
- **THEN** активне зображення (або контейнер слайдера «До / Після») плавно масштабується (зокрема `Fit` розтягує або стискає зображення на весь доступний простір, а `100%` встановлює точний масштаб `1:1`), і щойно масштабоване зображення перевищує видимі межі полотна, **над** кнопками масштабу з'являється вікно навігації, яке показує мініатюру зображення з рамкою видимої області та дозволяє перетягуванням/кліком переміщати область перегляду

#### Scenario: Single processed image renders interactive Before/After slider
- **WHEN** обрано один файл зі статусом `is_processed = true`
- **THEN** полотно завантажує оригінал та оброблену версію через `studio.get_image` і рендерить рухомий вертикальний розділювач «До / Після» з підтримкою миші/тач-подій, сумісний із поточним масштабом

#### Scenario: Multi-selection renders Apple Time Machine cascade
- **WHEN** у режимі виділення обрано 2 або більше файлів
- **THEN** відображаються до 5–7 передніх карток без зміщення вправо (`translateX = 0`), зі збільшеним вертикальним відступом, зменшенням масштабу та затемненням/зникненням у темряву при відході назад (`translateZ`), із використанням легких прев'ю (`thumbUrl`) для задніх карток та повного перегляду для передньої картки

### Requirement: Individual and Batch Result Controls
Користувач MUST мати змогу завантажити або відновити як окреме оброблене зображення (іконкові кнопки на полотні), так і всі результати одразу (іконкові кнопки `Restore All` і `Download All`, розміщені у Панелі керування одразу після `Process` і `Process All`), об'єднані у відповідні button groups з підказками при наведенні.

#### Scenario: Per-image Download and Restore appear on processed image
- **WHEN** активне зображення на полотні є обробленим
- **THEN** поверх зображення відображається згрупована панель іконкових кнопок `Download` та `Restore` з підказками (`title`)

#### Scenario: Bottom-right Download All and Restore All reflect processed count and busy state
- **WHEN** у `output/` немає жодного обробленого файлу або триває обробка
- **THEN** кнопки `Restore All` і `Download All`, розташовані у Панелі керування одразу після `Process` і `Process All`, є неактивними (`disabled`), а за наявності результатів і простою `Download All` скачує `.zip` архів через `studio.download_zip`, тоді як `Restore All` очищає всі результати

## ADDED Requirements

### Requirement: Icon-First Button Ergonomics, Button Groups, and Native Context Menu Suppression
Усі кнопки дій інтерфейсу MUST використовувати зрозумілі SVG-іконки з інформативними tooltip-підказками, суміжні кнопки в межах однієї панелі MUST об'єднуватися у візуальні групи (`button groups`), а стандартне контекстне меню браузера/веб-в'ю MUST бути заблоковане на всьому інтерфейсі.

#### Scenario: Action buttons render icons with accessible tooltips and connected group styling
- **WHEN** інтерфейс рендерить панелі дій (Панель керування з `Process`/`Process All`, `Restore All`/`Download All` і `Open Folder`, шапку Project Folder, групу дій на зображенні, дії версій і панель масштабу з `Fit`/`100%`)
- **THEN** кожна кнопка дії відображається у вигляді компактної іконки з `title`/`aria-label`, кнопки `Process` і `Process All` мають виразне зелене оформлення, а сусідні кнопки однієї групи візуально з'єднані в суцільну групу кнопок

#### Scenario: Default browser context menu is suppressed globally
- **WHEN** користувач виконує правий клік у будь-якій точці веб-в'ю
- **THEN** стандартне контекстне меню браузера не з'являється, а на елементах файлів відкривається лише кастомне напівпрозоре вікно деталей файлу
